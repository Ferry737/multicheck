## Justified floor — derivation

Satzbau's floor of 13 comes from `3 x per-struct servings` over an 8-week plan
where satzbau is a **daily** Deutsch subskill (52 structs, high rotation).
Alltagswissen has a different usage shape, so copying 13 is not justified.

Measured/planned inputs:

- Programme length: **8 weeks = 56 days**
- Alltagswissen appears in the daily plan roughly **every 3rd day** →
  `56 / 3 ≈ 18` sessions
- Per session the subskill contributes about **3 items**
  → total lifetime exposure ≈ `18 x 3 = 54 items`
- Items are drawn across **16 families**, so a family is visited about
  `54 / 16 ≈ 3.4` times per learner
- Exposure cooldown means a repeat inside the same session is the visible
  failure mode; across the programme a learner should not meet the *same*
  item twice.

Floor = (visits per family) x (safety factor for uneven family weighting)

    3.4 visits  x  3  =  10.2  ->  FLOOR = 11

Safety factor 3 covers: adaptive weighting (a weak learner revisits a family
far more often than average), the spaced-repetition second pass, and the
Mini/Full Simulation draws which sample the same pools.

**Adopted floor: 11 meaningful variants per family** (vs satzbau's 13, which is
justified by satzbau's daily rotation and larger per-session share).

Family 8 (money-change-counting) already sits at 176 because it is numeric and
combinatorial; that is genuine capacity, not padding.

## Anti-gaming rule

A variant counts only if it changes **what the student must decide** — a
different hazard, a different correct action, a different priority order.
Renaming a person or swapping a room does not count.
